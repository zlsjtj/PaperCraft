DEMO specification, not a real implementation claim.
Input record order is fixed. Existing data format has sequential blocks, each containing a length, sequence number, payload and checksum. A pre-existing sequential scanner finds the longest valid prefix; stop at first invalid block. Checksums detect the corruption considered here, not arbitrary adversarial collision. The scanner is unchanged.
Storage model: after a successful data synchronization, acknowledged data bytes survive modeled power loss. Before synchronization, a completed write may be absent or torn after restart. Progress slot writes may also be torn. Two slots occupy disjoint fixed locations; there is no proof against loss of both or dishonest device flushes.
Current procedure: append a block; synchronize output data; write the alternate progress slot containing generation, last-completed block number, end offset, and that block's digest; synchronize progress. Only then acknowledge that generation. Each slot has its own checksum. Restart checks both slots; among valid entries whose named data block validates, choose the largest generation and resume after it. If neither entry validates, run the unchanged full-prefix scanner. Finish flag uses the same order after final data.
A single invalid latest slot can make recovery choose the previous completed generation, so a valid block may be replayed. Replay rewrites from the selected prefix, not appended duplication. Input must still be available and deterministic. The procedure adds one progress-slot synchronization per block; this may dominate on some storage. No wall time, energy, flash wear or throughput result exists.
The simple offset-only comparator stores the offset immediately after the write returns. It need not wait for durable data. This comparator is not safe under this crash model. The old full-prefix scanner is safe and has no side-progress synchronization cost.
Generation and checksum slots are common techniques; no prior-art search has established novelty. The exercise asks what this concrete combination changes relative to this code baseline, not whether it is a new recovery algorithm.
