# 从未整理记录组织栅格传输论文

原稿、实现说明、12行结果和研发记录均为原创DEMO，不是真实实验，也不用于支持科研性能。生成任务只提供这些材料和长度/文件约束，没有预写主贡献。普通提示、修改前技能、候选技能各在独立上下文生成一次首稿，再自主复读一次；首次文件未被后续意见覆盖。

## 选择发生在哪里

修改前技能已经找到了合适的安全基线，并没有把继承的原子发布包装成新发明。问题更窄：引言提早放入指针数、单元数、字节数，打断两块数据更新的例子。候选技能在资料散乱时先写出两种实际入口，再择一续写；两段和淘汰理由见 [candidate/decision.md](candidate/decision.md)。它最后先讲到达顺序如何产生混合视图，再解释已有发布能力和补丁传输要解决的剩余问题。

匿名模型评阅先读同等范围的开篇，再读来源和全文。候选开篇更容易进入；这不是实测阅读时间，也不证明全文、所有任务或审稿结果全面胜出。旧版将合格成本对照和IT诊断分表，更直接地分清证据职责；新版一表保留全部记录，查齐数据容易，但主对照的视觉邻接不如旧版。详见[匿名最终评阅](review/final-assessment.md)和[条件对应](review/identity.md)。普通提示自修还把一致性误写成节省通信量的必要条件，并含混地说收益反转；错误稿作为比较材料保留，不能用作推荐清稿。单独修正只恢复“节省字节”和“应用一致性”的区别，并限定反转的是延迟，不改变原匿名判断。

此材料被维护者用于选择窄范围修改，因此候选试用是开发对照，不称未见材料上的严格独立检验。执行者未见其他稿件或维护者判断；三组模型设置相同、任务范围相同，实际token未严格控制，没有重复采样或真人评审。普通提示同样生成了较好文本，未将其作差来证明新版。

## 文件与重建

`input/`保留全部原始材料。三个条件目录均含first、final、一次自修记录、清稿和审阅稿；黄色相对各条件自己的首次完整稿，**不是原始研究草稿，也不是Word原生修订**。原始draft与最终稿可直接逐段比较，移动/删除不由黄色完整表达。数值核对逐格比较12行全部指标；没有公式、参考文献或图片时不虚报这些项目已测试。

Python需要python-docx。以下从仓库根目录执行，目标目录须是新目录：

```powershell
python examples/raster-publication/build_documents.py --source examples/raster-publication/candidate/final.md --baseline examples/raster-publication/candidate/first.md --out output/raster-candidate
```

该脚本只排版已写成的文字，不会自主提炼贡献。要检验生成能力，另开执行上下文，仅提供input与相应技能；不要同时提供candidate或评阅答案。PDF须再用宿主documents渲染器、LibreOffice和Poppler生成并逐页检查。示例中已提供本次实际渲染的PDF。
