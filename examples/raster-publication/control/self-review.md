# 一次自修记录（DEMO）

这是生成者自己的阅读与事实核对，不是独立模型、真实同行或作者验收。`first.md` 是首次完整稿且未覆盖；`final.md` 只经过一次自修，没有外部反馈后的补写或重复采样。所有数值仍为原创合成夹具。

## 实际收益

- **保住强对照并改善阅读顺序。** 首稿十二行混排，FS→IT→SP 让不满足一致性的 IT 数字打断有效比较。终稿先给 FS/SP 相邻八行，再给保留全部指标的 IT 诊断四行；正文先判断额外协议是否值得，再解释低延迟何以不等价。
- **修正首稿留下的方向歧义。** 首稿写 “Payload retention declines ... to ... 1.06, 1.38, and 1.94 MiB as changes become denser.” 它试图比较 FS，却可能被理解为越密集越少占内存。终稿明确写 “SP retained payload grows ... approaching FS's 2.00 MiB.” 这是事实表达修正，不是仅缩句。
- **补回遗漏的模式与口径。** 首稿只在表中写 24 tiles，没有明确 moving-front；也没有明确 wire 数据包含 framing。终稿补足这两项。首次稿的缺失保留，不宣称初次已全做到。
- **限定一个过强的一般句。** 首稿 “Sending an intermediate value would not reconstruct that target” 过于一概而论；终稿限定为随后又改变过的瓦片，避免暗示所有中间值都不同于最终目标。
- **方法证据更贴近职责。** 28 条功能轨迹及失败变体移到评价；Discussion 用其边界解释采用条件，不再兼作功能结果清单。内存元数据在方法给出，结果处只解释表中分母与读者条件。

## 保留的损失与不足

- 分成两表后，IT 与 SP 的差值不如首稿相邻行好找；接受这一代价以明确主要比较的资格。
- 终稿增加表题和评价连接文字，不以词数下降宣称减负。方法仍包含较多失效分支，尤其重复包、断连、过期包与基准回退一段较密；删掉会改变协议含义，本轮保留。
- 首稿的双瓦片实例在引言和方法各用一次，终稿也保留这种重复以连接问题与动作；不能据此宣称所有冗余均已消除。
- 没有实际 Word/PDF 页面验证；Markdown 结构与数字核对不证明视觉完成度或真实读者更易懂。生成者判断终稿主比较更清楚，但未测理解效果。
