# Notebook excerpts and sources (DEMO)

[N1] All rows in results.csv are authored synthetic fixtures for this skill evaluation. They are not output of a real benchmark and cannot support deployment, publication novelty or statistical-significance claims. Units KiB and MiB are binary; wire bytes include protocol framing. Payload retention excludes pointer tables and descriptors from I6.

[N2] Same 120 target roots per row, same lossless tile values, same packet schedule within a workload/link pair. Median/p95 summarize completion delay from producer target publication to all packets needed for that target being applied/staged; IT is included diagnostically even when its reader-visible intermediate roots are incoherent. A low IT delay is not a valid coherence-preserving performance baseline. Coherent_roots counts runs with no non-target mixed root observed at ANY prescribed reader interleaving from request to completion, not only whether the final root eventually matches. Prescribed interleavings are a finite fixture, not all schedules. The resulting criterion distinguishes IT from FS/SP; FS already satisfies it.

[N3] Three changed-tile patterns, two link regimes; only sparse was included under fast_local. There is one fixed schedule per case and no confidence interval, repetition, stochastic loss model or CPU microarchitecture study. Queue budget and retry deadline fixed at 32 packets and 20ms for all table rows. An older 64-packet exploratory run is excluded, not mixed into the table. Tile serialization and transport implementations are identical across methods except for required payload selection and manifest handling. It is not valid to claim every difference in latency comes solely from byte count.

[N4] Separate functional suite: 28 hand-authored protocol traces. SP matched the target-root oracle in all 28. Cases covered first connection without base, empty patch, delayed final tile, reordered packets, duplicates, conflicting duplicate, payload corruption, disconnect during staging, late packets after reconnect, base eviction, and two pinned readers. Eight base-eviction/reconnect traces took FS fallback. No recovery latency summary exists for these 28 traces; do not combine with results.csv or claim retention of the sparse-path byte benefit on fallback.

[N5] Development variant without base checking: 2 of 6 reconnect traces exposed mismatched roots. Variant that acknowledged upon first packet rather than publication: 1 of 6 reconnect traces failed after coalescing. These are functional failures, not timing ablations. Coalescing generated target values once per coordinate and the range checks rejected malformed tile IDs. Allocation-failure injection and process-crash testing are not implemented. Client-server security, authentication, and adversarial Byzantine behaviour are outside scope.
