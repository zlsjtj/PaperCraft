# 本例验收与边界

## 已执行

- 从原始 `source.docx`、实现说明、CSV 和原图生成完整英文稿与机制图；原文件保留。
- PaperCraft 正式文字适配器生成清稿与黄色稿，正式替图适配器替换 PNG，实际绑定检查确认 160×85 mm 与确切图注。
- FigureCraft 导出 SVG、矢量 PDF、PNG 和场景 JSON；PDF 字号检查最小 9.448819 pt。生成模型查看正常色、灰度及单一色觉模拟。
- 第一份完整稿在一次自审之前保留。实际观察到的引线穿字问题和摘要表述问题有首稿及修复记录。
- 主编辑者检查自修稿清稿、黄稿和简报共九页后，发现表头代码式断词。后续专用版式步骤改为易读表头；九条数据行的完整规范化 XML、非表正文、全部媒体及其他 ZIP 部件保持一致。整表 XML 有授权变化。

## 重建与页面状态

六脚本使用显式输入、技能、字体和 Poppler 路径；目标目录拒绝覆盖。公开目录复制到新目录、从不同工作目录按 README 重建的结果记录在 `rebuild-validation.json`。

实际重建已成功：首稿、自修稿、最终交付清稿/黄稿及所列 PNG/SVG 共九项字节一致。公开文本源、DOCX 全部 XML/关系和 PDF 元数据/可提取文字的本机路径检查无发现。初次表头收尾的 OOXML 属性顺序也已在脚本中纠正；最终 `trPr` 和 `rPr` 位于所属内容之前，九条数据行继续原样保留。

安装后的跨盘试用还发现一项路径问题：用`os.path.relpath`直接连接输入原图和输出报告，在不同盘符下会失败。同盘重建没有覆盖它。现改为将原图复制到新输出内的`report-assets/`，以局部相对路径交给报告工具；正文、图形与数据不变。失败日志保留在本地，跨盘复跑单独记录，不倒写为首次已通过。

最终表头修复稿的清稿、黄稿各3页，以及新版简报3页，均已由主编辑者渲染并逐页查看。9页没有观察到裁切、重叠或黄标错位；表头粗体与列宽实际显示正确。`page-check.json`绑定确切DOCX、PDF和页面哈希。简报是在该复验之前编写，其中“待页面复验”的当时状态由本收据接续关闭；不是脚本自动给出的视觉结论。
