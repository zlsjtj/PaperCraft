# 实验叙事与投稿方向

用于实质性重组，以下问题不是必须照搬的论文标题。主线见[审阅方法](reviewer-method.md)，工程展开见[工作量](workload-framing.md)。

先检查已有表格、实现分析和保留测量中是否有未被讲清的结果：它回答哪项成本或实际选择，分母包含什么，来自主机制还是共同设计。只有增加了独立答案，才值得前移。

派生统计要能回到原始数据。事后分层应标为探索，相关负例保留。不能把调参数据改称留出测试、把重复测量记作独立证据，或擅自增加实验。

| 问题 | 所需证据 | 解释边界 |
|---|---|---|
| 机制是否正确且可实现 | 依赖论证、分配、数值检查和生成代码 | 模拟和静态检查不证明物理性能 |
| 目标约束是否改变 | 活跃值边界、资源映射、指令检查 | 静态数量不等于动态访存和停顿 |
| 同一计算采用新执行方式是否获益 | 因素匹配的对照 | 不等于独立优化后端的完整排名 |
| 收益能否保留到完整应用 | 开发集选配置，留出负载验证 | 不得在测试集重新调参或删去负例 |
| 何时有效、无益或不可用 | 分层、中性结果、损失和实际成本 | 未测原因仍为假设 |
| 是否有次要资源收益 | 明确边界的复用、体积、准备或转换测量 | 内核字节不能外推部署、编译时间或能耗 |

内部记录应包含实际实验单元、独立输入数、平台与线程、配置选择来源、启动次数、重复和排除项。不同检查有不同作用，不相加为夸大的工作总量。

负结果按观察条件、可支持解释、合理选择来写。容量允许更宽分组而某例变慢，不等于已测明缓存原因。有用的备选不必是默认赢家，但未实现的盈利预测器不能写成已有功能。

投稿方向应根据目标期刊当前官方范围、作者指南和相关论文核查。计算工作负载、体系结构适配或系统工程可以是强调重点，却不构成编辑部接受规则。不同期刊版本共享同一证据底稿，投稿信和亮点不能比正文说得更强。图文摘要仅在用户要求或已核实规范有需要时制作。
