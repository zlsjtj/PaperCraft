# 从审阅者的问题出发修改

适用于全文精修和重大贡献重写。先连读标题、摘要、引言与主结果，再读全部方法和实验。目标是让审稿人有依据地接受一个值得关注的判断；找到段落里的信息，不等于已经被论证说服。不要预测接收率，也不要借流畅叙事掩盖研究缺口。

| 问题 | 可执行的修复 | 不能替代的工作 |
|---|---|---|
| 贡献埋在实现细节里 | 写清约束、变化与后果 | 原方法中不存在的新颖性 |
| 相关工作只有列表 | 比较最接近机制的实质差异 | 未阅读论文的比较结论 |
| 工程步骤互不相关 | 沿执行链解释接口和不变量 | 将常规搭建升级为新算法 |
| 实验很多却不支持结论 | 让对照回答明确问题，说明独立样本 | 缺失对照与未做实验 |
| 有效结果被重复限定淹没 | 直接陈述结果，附影响含义的条件 | 删除不利的整体结果 |
| 表达模板化 | 使用具体对象、机制和贯穿示例 | 同义词替换、虚构缩写或装饰性复杂度 |

## 从材料中找主线，再改入口

原稿、实现笔记和结果表尚未整理时，先不把原稿标题或作者列出的贡献当成结论。沿一项具体操作追踪旧方法与当前实现：输入后发生什么、谁等待或持有资源、在哪个条件下行为不同。把每个差异连到实际源码说明或记录位置；未记录的中间行为留作缺口，不用合理想象补齐。

在内部把材料分成“基线已有／本次改变／使改变成立的条件／检验了什么”。这是整理散乱材料的草稿，不是要求论文增加四个部分。先找能改变读者判断的连接：某条看似琐碎的实现条件是否避免了具体失败；某个负例是否表明优势来自另一因素；某项完整成本是否推翻局部指标的印象。只有来源支持时才把这些连接写进正文。

定位仍不清时，用同一组事实写出少量不同的中心判断。例如以新增能力、必要协议或有判别力的发现为中心。分别问：即使完全承认基线已有的能力，剩下的改变为何值得做；当前比较能支持这个改变，还是只支持含多项变化的系统。选择能被现有证据完整支撑的路线，随后直接改稿。不能靠把机制名称写进标题，就把尚未隔离的收益归给它。

## 让全文回答同一个值得研究的问题

在现有全文对应表上写一句待论证的判断，并定位使审稿人改变看法的比较。它不是宣传口号或三项贡献清单。例如虚构预约案例的判断是：队列中仍有取消节点时，槽位所有权与队列成员关系分离，可以提前恢复接纳能力，但不意味着总体效率提高。见[完整接续示例](result-pair-example.md)。

对这条判断找少数真正有威胁的替代解释：收益是否来自弱基线、额外调参、改变比较范围，或另一个已知组件。已有证据能回答时，将回答写到对应方法或结果中；不能回答时收紧该判断或标出研究缺口。不是要求每篇加入同一组实验，更不能开展未经授权的实验。用过多泛化免责声明代替具体回答，也没有完成论证。

据此给各节安排不同职责：引言建立值得解决的后果与剩余困难；方法解释为何简单做法不够以及关键决定如何解决；实验让读者知道每个比较在排除什么；结果直接说明比较允许得出什么；讨论解释这些判断在哪些条件下不再成立。章节标题可以不变，但章节之间要推进判断，不能反复从头介绍同一机制。完整参数留在其使用位置。

重要工程工作的篇幅按其对中心判断的作用分配。挑有来源支持的错误路径或约束，说明漏掉某个决定会失去什么能力、破坏什么条件，再承接实现及检查。普通搭建不抬高为创新；决定成败的工作也不能因没有单独速度数值就被压成清单。实例只解释已有事实，不暗示额外实现或实验。

全文修订至少检查引言到方法、方法到实验、结果到结论这几处接续。某处已有连接就保留；缺连接时优先改段首、重排已有证据、替换重复句，不默认新增一段。图表同样要承担其中一项论证任务，而不是在正文旁另讲一遍所有细节。

用一项具体过程或失败场景解释必要决定，再沿该过程核对正常路径、退出条件与不能提前发生的动作。入口说变化与价值，方法承接这些条件；结果按[论证修复](argument-repair.md)把同一比较的收益、代价和反例一起改写。缺少外部最近邻或独立消融时，继续改善已有事实的表达，在相应归因处保留缺口，不把缺口反复写成段尾警句。

主线已有充分依据且清楚时只需精修。此流程不证明文献首创，也不保证一定存在值得强化的新贡献。

## 比较与措辞

优先比较最接近的系统，而非弱通用基线。已有方法完成的部分应承认，再解释剩余变化。准确区分新机制、已有技术的新连接或规则、实质移植、复现与评估、局部优化。

只有匹配对照或可辩护推导才支持机制归因。整套后端比另一套系统快，通常不能独立归因于一个组件。

| 证据 | 可支持的说法 | 不能直接推出 |
|---|---|---|
| 有前提的证明 | 前提下的性质成立 | 前提外的普遍最优 |
| 容量或资源表达式 | 给定约束下足够或合法 | 总是最快、最小或实现必然可达 |
| 指令与静态清点 | 检查构建中的指令或存储 | 动态访存、停顿、能耗或实际时间 |
| 数值与模拟检查 | 指定环境和案例通过 | 物理板卡的正确性与性能 |
| 完整匹配物理对照 | 改变因素在这些条件下的效果 | 所有端到端差异均来自该因素 |
| 完整留出应用测量 | 该样本和协议下的结果 | 任意负载上的优势或部署成熟度 |
| 有根据的解释 | 观察与某种解释一致 | 已经测明硬件原因 |

选择形容词前先明确基线、总体、指标和汇总层级。“显著”若指统计显著，需要相应分析。控制失败或独立运行波动未解决时，不能宣称稳健。

## 技术深度与阅读

先定义概念，再引入符号；用一个可靠示例暴露依赖或约束。保留使设计可检查的公式和不变量，详尽参数表可放复现材料。解释接口约束和没有它会出什么问题，往往比增加段落更有效。

标题、摘要、方法和图使用稳定术语。已证实能力放主句，改变含义的限定贴近主张；详细边界集中讨论。若省略整体负结果会误导，摘要中就应保留。

## 检查改稿效果

先让审阅者按自然阅读顺序说出：论文希望自己相信什么，为什么值得相信，哪项比较最关键，哪处仍不能被说服。再查事实、归因和完整性。若回答只是“使用了若干模块、做了很多测试”，说明主线仍未成立；若把系统收益归给未做消融的组件，则需修正表达。不要把这项练习冒充真实同行认可。

比较前后稿时指出哪一处推理现在可以直接跟上、哪项重要工作更显必要，以及为此付出的密度或歧义代价。只检查科学错误的审阅不能替代这种比较；“没发现新错误”不构成无需改善的理由。反过来，已经流畅且有依据的段落不为显示工作量而重写。按[读者效果审阅](reader-effect.md)记录原句和位置，不用主观总分掩盖退步。

记录可观察变化，例如明确了基线、删去重复、连接了证据、修正了分母。字数只用于控制长度，不编写作分数、AI 分数或接受率。

全文请求交付实际稿件；局部请求只处理对应产物。必需实验未完成时可先修改已支持部分，但不把准备工作写成最终成果。写作任务不默认授权上传、投稿或联系期刊。
