# 工作量的六个真实维度

| 维度 | 核查与补写动作 | 无记录时 |
|---|---|---|
| 背景 | 明确对象、约束、需求、影响；删无关宏大背景 | 不编产业规模或使用需求 |
| 研究现状 | 最近邻技术差异与必要相关工作 | 标明文献未核实，不补假引用 |
| 参数与标定 | 来源、含义、范围、经验选择/搜索/理论依据、选择数据 | 写实际经验设定；标定过程待确认 |
| 实验或模型 | 构建、边界、干扰、控制、条件、计时范围 | 不把计划检查写成已完成 |
| 重复 | 区分样本、工作负载、设备、启动、重复运行、共享原始单元 | 不用重复数充独立覆盖；新重复属于研究 |
| 验证 | 正确性、公平对照、数值条件、失败与排除、外推范围 | 无检查不能写通过；原因不明保留不明 |

## 从清单到解释

对有意义的工作写：困难 → 简单做法为何不够 → 设计决定 → 不变量/接口/条件 → 实际验证 → 作用。例如共同执行器让比较保持同一所有权与状态接口；它支持可比性，不自动证明多线程加速。

内部记录“已完成工作—读者能否看见—支持主张—应放位置—是否重复”。不要把代码行、脚本数量、运行总次数当创新。系统论文进一步参考 [工程工作流](packaging-workflow.md)。

## 三种新增内容

1. **新增文字**：补写已完成的步骤，引用代码/记录或标明仅原文报告。
2. **新增分析**：对既有数据或假设明确的公式作可复算分析；留输入、算法/脚本、时间、比较对象与范围，标明探索性。新增解释不等于新测量。
3. **新增研究**：新实验、平台、样本或测量；未获授权不执行，未完成不写结果。

调参事后理由不能改成实验前理论设计。只有公式容量不能写动态带宽/能耗。速度比 `T_base/T_new` 与时间降低 `1-T_new/T_base` 不混用。统计单位、分母、排除和失败保持一致。

## 让 Discussion 更充分

每段回答现有材料能回答的问题：机制解释、最近邻差异、条件/参数依赖、边界、应用、成本或未解限制。不利结果可帮助界定条件；原因未测不能擅自归因。跨设置复制同一观测不产生新独立支持。

扩写不是字数任务。材料只有两项，就写清两项；需补研究的内容进入报告。未完成实验只冻结依赖它的结果，其他解释与图文仍可交付。
