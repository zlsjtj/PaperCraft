# 长稿与复杂 Word 的受控修订

适用于原生公式相邻段、混合 run、引用域、交叉引用、图表及已有高亮/修订。`review_docx.py` 拒绝这些目标是保护措施，不是停止任务的理由。普通文字的局部续改先走随包 `replace_span` 路径；它保留公式、域结果、链接、旧高亮及原生修订。超出支持范围时，使用宿主实际可用的格式感知流程，沿用本文件的对象保护方法。一个主编辑持有最终 Word。

## 可直接执行的文字片段路径

先用 `review_docx.py inspect` 取得目标段号、完整 expect 和输入哈希。不要仅看兼容字段 `editable`：它表示旧的整段局部结构判断。读取 `whole_paragraph`、`ordinary_spans`、`document_blockers` 和 `recommended_route` 决定工具路径；复杂段 editable=false 仍可有可执行普通片段，文档有历史修订时普通段 editable=true 也不能整段替换。

从 `ordinary_spans.groups` 选择 `replaceable_as_whole_group: true` 的组，按其 `operation.target`、`operation.before` 填写计划；run_locations、paragraph_child_indices 与 format_sha256 标明连续同格式组的来源。需要更短片段时，只选该组内单行原文，并确认在该段全部 eligible 组中唯一；构建时仍按同一匹配规则复核。重复的组会列出但不提供可执行 operation。protected_content 给出不能改写的域缓存、公式、链接、高亮和历史修订的位置。

沿用原 build 命令，将操作写成：

```json
{"id":"C1","kind":"replace_span","target":"P0003","expect":"inspect返回的完整原段",
 "spans":[{"before":"待改的普通文字","after":"有依据的新文字"}],
 "purpose":"本处阅读或科学问题","evidence":"具体材料位置","confirm":false}
```

同一段多个替换放在一个 spans 数组；每段只列一次。匹配必须在一个普通文本区内唯一，允许跨相邻且格式完全相同的run。遇到不同样式、公式、链接、字段代码或结果、历史高亮、原生修订就停止该匹配，返回段号和具体片段，不把这些节点改造成纯文本。表内文、任意跨段重排和原生修订内的修改尚不支持。若阅读改善需要在普通文字边界拆段，使用下述受控适配器。原生修订的显示方式由编辑器控制，清稿保留它们，不等于接受历史修改。

一份计划只走一条操作路径。有复杂片段目标时，其余普通段也从清单选组并使用 replace_span，不能混入 replace。插入整段、删段、移动和段落格式操作若可用且属于授权范围，需要独立 build；后续计划重新 inspect 该产物以更新 expect、段号和父哈希。不要为了拼成一份计划绕过历史修订保护。

inspect 遇到异常域结构会保留只读清单，返回 `field_structure.status: BLOCKED` 及 XML 位置，并关闭所有编辑路线；build 以相同字段判定拒绝。域文字仍保留，不能把格式异常解释成普通可改文本。

Word 的 `w:lastRenderedPageBreak` 是上次排版的缓存位置，不是显式分页或作者修订。单一文本节点旁只有这类缓存的 run 可走 `replace_span`；清单用 `retained_layout_cache` 定位。缓存前后各保留一次，改写与黄标不复制它，也不允许匹配跨越缓存 run。缓存位置不保证改稿后仍是实际分页，需重新渲染。真正的 `w:br`、域结果、旧高亮和修订仍受保护。

审阅稿只给新文字加黄标；清稿不加本轮黄标。已有绿色/黄色高亮和历史插入删除保持原XML。任何片段失败都不发布半份候选。重新选择明确可编辑片段，或将不支持项记录为原样保留；不能改成整段 replace 绕过拒绝。

局部任务的 report 只需 summary，可附 limitations 和 checks；全文 report 的贡献/证据字段继续保留。复杂教学例和可执行命令见 `examples/complex-word/README.md`。

### 写作补丁含有拆段时

`scripts/apply_authored_edits.py` 接收已经过内容审阅的编辑 JSON；它不决定怎么写论文。普通片段用 `replace_span` 或可由同一普通文本区承载的 `replace_paragraph`，分段用 `split_after`。这些路径均从原 DOCX 匹配原文，不清空重建段落。`after` 中的双换行可表示明确的新段边界；任意单换行不支持。

已经写好的连续段落可能只因 Word 将同一西文字体拆成不同 `w:rFonts/@w:hint` 而不能成为一个 span。先保留具体拒绝，再看 `inspect` 的 `authored_prose_diff` 能力项。可用时，以 `operation: "rewrite_prose_preserving_runs"`、准确的完整 `before` / `after` 和输入哈希交给同一 CLI。工具按词计算最小差异，清稿保留所有原 run 与 rPr，只改普通 `w:t`；仅对 ASCII 文字、显式相同的 ascii/hAnsi 字体，允许 eastAsia/default 字体提示的差异。真实字体、语言、斜体、上标及其他格式差异仍不能被一次差异跨越，书签、域、公式、旧高亮和缓存分页仍是边界。含历史修订的目标段不走此路线。能力项仅表示存在接续入口，具体 `after` 仍须逐区验证。

这个操作不与同段 span 或 split 混用。新词在审阅稿中黄标，原样保留的词不标；删除内容在 `text_diffs` 中记录。拒绝后应检查所选改写是否触及真实格式或书签意义，不去掉格式、移动保护节点或机械拆散同一改动以绕过边界。原稿已有清楚句子时可保留；需要改它且本路径不能安全完成时仍进入宿主可用的格式感知处理并注明具体范围。当前支持和拒绝样例见 `tests/test_authored_run_rewrite.py`。

拆段只在普通文本 run 的边界或内部执行，复制段落属性并移动既有后续节点。公式与链接可以完整留在原段或移入后段，不能被切开；含字段、历史插入删除或节属性的目标段拒绝拆分并给出原因。其他段的历史修订保持。输出清稿、仅新文字黄标的审阅稿及原段到新段的映射；拆分本身不冒充原生修订。

使用方式与演示输入见 [安全拆段示例](../examples/authored-edits/README.md)。使用新目录构建；失败产物不能作为交付。成功后仍需重新渲染，判断分段是否改善连续阅读，而不是仅增加段落数量。

选稿把同一要求的两段文献合成一段时，可在重新 inspect 后用同一 CLI 的 `join_next`，不清空重建文字。计划须给确切 `source_sha256`、目标 `paragraph_id`、完整 `before`、相邻段的 `next_before`、合并后的 `after`、`reason` 和 `source`；`separator` 只能是空串或一个普通空格，`after` 必须严格等于两段原文加这个分隔符。它只合并物理相邻且 `pPr` 完全相同的段，移动现有子节点并将两个原段 ID 映射到同一新段；不同段落属性、域、节、历史修订、评论、显式换行或非文字对象仍拒绝。合并须单独一轮，不能顺带移动、规范化格式或与文字改写混用。相邻合并改变论证单元，不证明内容分组正确。

自修需要改动先前新加的黄色文字时，不应删除高亮或放宽“旧高亮受保护”的规则。保留首稿，将最终累计文字计划重新应用到冻结源，再生成清稿和累计黄标稿；来源里本来存在的高亮与历史仍受保护。保留各阶段计划和映射，验证最终全文等于选定文字，而不是交付只有最后一步黄标的稿件。

## 修改前

冻结原稿、哈希及图源/数据来源；读取所有正文、原生公式、表格、图注、参考文献与声明。为要动的段落建立稳定 ID 和准确原文断言，记录标题层级、段落/run 格式、域、书签、超链接与关系目标。用相邻短引文定位，最终页码由渲染确认。改前先写阅读问题及四项修改理由，避免把全文扁平化后重建。

## 修改方法

- 普通纯文字段可用现有 helper。公式相邻段只改授权文字节点或文字片段，保留原 `m:oMath` 子树与其顺序；若重排文字，用独立占位符绑定每个公式节点，插回原节点，逐一断言出现一次。不得用公式显示文字重造公式。
- 混合格式段要按文本片段保留格式。例如段首加粗标签不能因沿用第一个 run 的属性而把整段变粗；移动或改写标签后，应同时核验标签范围和正文范围，再查看实际页面。普通 helper 已拒绝 mixed run formatting，格式感知接续脚本也必须保留这一边界。
- 保留脚注标记、引用域、书签边界、超链接、图关系和表结构。允许文字变化不等于允许破坏这些对象；无法安全处理的对象留原样，继续其它修订，并明确具体缺项。
- 图修订仅替换对应图像及可编辑源，保持关系 ID 可解析，按真实入稿尺寸核验。对象数不变仍要检查数值、含义和图注；只换色任务不得顺带改布局或图内内容。
- 新黄标只标本轮新增/重写文本。不要把数学节点整体重构成高亮文本；公式内容保持不变时，在报告定位周围文字修改。清稿只移除本轮黄标，原有高亮/原生修订保留。
- 对新增、删除、移动、格式与图片替换都写变更映射；无原生 Track Changes 就明确是黄色审阅标记。报告不应声称黄色标记呈现了删除。

## 让重排进入实际 Word

连续稿已经确定应移动的图、图注、结果段或表格时，不能因为段落补丁只会替换文字而放弃重排。`move_body_block.py` 移动完整连续 body 对象块，保留每个子树与其他 ZIP 部件；它不重建图片、表格或公式，也不替编辑者决定顺序。

```text
python scripts/move_body_block.py inspect current.docx --out body.json
python scripts/move_body_block.py move current.docx move.json reordered.docx
```

`move.json` 从确切输入的清单取值：`input_sha256`、一基 `first` / `last` / `anchor`、`placement`（`before` 或 `after`）、按原顺序的 `block_xml_sha256` 数组及 `anchor_xml_sha256`。一次移动一块，下一次重新检查新输入。它拒绝切断书签/复杂域、穿过节边界、块内历史修订，以及包含评论范围或历史移动范围的文档；未支持的结构不默默扁平化。普通文字改写与移动分开执行，并维护原段身份映射。图号与正文指向另行更新，完整图表和其图注仍须对应。

接续脚本完成后，把每个改动段的最终全文与编辑者选定文字精确比较；部分 span 成功的中间稿不可作为成稿。再检查被移动对象的身份、图文指向与实际页面。XML 保留只证明对象没有被改写，不证明阅读顺序更好。

## 内容保护检查

运行只读检查器：

```text
python scripts/audit_preservation.py original.docx revised.docx --policy protection.json --out preservation.json
```

最小 policy（文字必须来自原稿，不能把示例当保护内容）：

```json
{
  "protected_paragraphs": [
    {"label": "AI disclosure", "text": "Exact paragraph from the source."},
    {"label": "Reference 1", "text": "Exact first bibliography paragraph."}
  ],
  "lock_citation_tokens": false
}
```

省略 policy 仍能检查原生公式、表格、图数量、域/书签/链接身份、脚注/尾注与参考源部件。声明和手写参考文献依赖明确 policy；未提供标为 **NOT_CONFIGURED**，不得声称已保护。受保护段按完整可见文字匹配，必须在源稿有记录；需要保留格式时使用 `"mode": "xml"`（默认 `"text"`）。同文段多处存在时要求两稿出现次数相同。`lock_citation_tokens` 可锁定数字方括号引文的多重集合；不认识作者年份引用，也不验证文献真实性。

检查器分别记录：

1. 公式 `m:oMath` 的数学结构/文本签名与独立 C14N XML 签名，按原顺序逐个比对；纯 run 外观不同进入 XML 审阅，数学内容变化失败。它不证明数学推导正确。
   两稿均无原生公式时，公式两项为 `NOT_EXERCISED`，不把空集合一致称为原生公式能力已验证；仅一稿为空时仍按新增/删除公式检测失败。普通文本中的数学记号另按改动段核对。
2. 表格行/单元格顺序、文本、公式、合并属性；不能只凭两表数量相等通过。
3. 域代码、书签名称、超链接关系、注释引用及图数量；图内容允许按当前任务变化，另走交接和视觉审阅。表格重排、公式重排或新增默认会失败，授权实质修改需另行逐项审计，而非关闭整个检查。 已授权移动完整段落时，保存原段 ID 到新顺序的映射；按原段 ID 和段内公式序号比对数学内容及 XML，再核对全文无增删、域/书签/关系和表内容。默认顺序检查的失败保留原回执，另写受控移动复核结果，不把默认失败改成 PASS，也不用无序计数掩盖位置错误。
4. 附属脚注/尾注/文献源部件与关系目标、明确保护的声明/文献段。

每项记录输入输出哈希、状态与差异索引。默认检查不锁定所有普通正文数字，也不能识别所有第三方 Word 扩展。仍须从变更映射逐项核对新旧数字、单位、地址、比较对象、声明、引用与公式周围论证。

## 最终交付

渲染审阅稿、清稿和中文报告，查看每一页；核对 Word/PDF 的公式、分页、表头、图内文字及字段结果。分别记录结构保护、科学内容审阅、视觉审阅、作者认可。受控 OOXML 的一份长稿通过，不代表所有复杂 Word 文件都已覆盖。

使用原生 Word 自动导出时，在只读任务副本上先完成 `Repaginate()` 再导出 PDF；导出后仍核对实际章节编号及目录/域结果。曾有不改 numbering.xml 的文本修订在首次导出中出现重复章号，重新分页和新实例复验均恢复正常。不能因此改写正文编号来迎合一次错误渲染，也不能将这个个案推为所有 Word 版本保证。只控制本任务创建的 Word 实例，关闭文档时不保存；来源哈希须保持不变。

## SVG 和 PNG 双表示

DrawingML 的 `a:blip` 可能只是 PNG 回退图，`asvg:svgBlip` 另指一个 SVG。不同渲染器会选用不同表示；只替换其中一种会导致论文仍显示旧图。新版入稿清单可逐图添加 `representations` 数组，每项含 `kind`（`primary` 或 `svg`）、`media_sha256`、`source_asset` 和 `source_asset_sha256`。主图原字段仍保留，表示集合必须完整。文件相同只证明绑定，仍要查看最终页面。

`audit_figure_integration.py` 会核对两种嵌入内容与各自导出。多表示图片沿用旧清单时进入待审，不能拿只核对 PNG 的结果当整张图通过。每次替换后重新渲染；记录失败首轮和修复后的确切文件。
