# 让读者先理解变化，再记住名称

适用于贡献入口不显著、读起来像技术清单的实质修订。先读实际入口并写出它要求读者同时理解的概念和关系；术语数量只帮助找问题，不设机械上限。

## 按理解依赖组织

读者第一次遇见专门概念时，能否从前文知道它是什么、为什么现在需要？例如“共享表”出现前应知道什么重复工作值得共享；“安全所有权”出现前应知道什么并行写入可能互相干扰。已有读者基础允许直接使用的领域词不必重新科普。把尚未有作用的定义后移，比换成模糊代词更有效。

| 层次 | 读者带走什么 | 如何安排 |
|---|---|---|
| 主贡献 | 相对已有机制，哪种能力或执行关系改变了，解决了什么困难 | 入口的主句，随后给理解该变化所需的支撑 |
| 支撑设计 | 使变化成立必须解决什么问题 | 用障碍与必要决定连接主贡献，完整条件到方法 |
| 证据 | 哪种比较支持哪项判断，并排除了哪种替代解释 | 先说问题再报结果；不把验证次数当贡献 |
| 边界 | 哪种条件改变眼前结论 | 紧邻相应结论，复现条件在方法，不用重复警句冲淡主线 |

不规定贡献条数。一个机制的地址分解、复用和边界检查不自动成为三项独立创新。已有分组或算法应明确承认，但不需要每段重新声明。

## 标题指向什么，结果实际测了什么

把标题中的动作或性质还原成完整关系：谁被复用、谁被选择、什么得到验证、比较测的是组件还是组合系统。“可复用的批次”和“跨批次复用的表”不是同一对象关系；压成复合修饰语后仍应准确。若标题首先突出一个支撑组件，而主要结果评价整个执行选择，比较以能力变化为中心的标题，不在末尾追加长串免责声明补救。

机制名称可以出现在标题中；没有单独计时消融，不等于不能命名该机制。要避免的是让标题把整体收益因果归给单一组件，或让读者误认被操作的对象。描述机制、主张性质、声称性能是不同强度，按实际证据选择。详见[检查点标题对照](worked-examples.md#标题与证据对象)。

## 在写句子前选择入口

只对有实际阻碍的位置比较少量路线。例如：

- 从阻碍进入：现有执行在哪里受限 → 新关系怎样解除该限制 → 为此必须解决什么 → 证据。
- 从新增能力进入：先给读者可理解的操作变化 → 用一个实例说明它为什么有价值 → 条件与证据。
- 从可判别结果进入：先给关键比较 → 解释是什么设计使这项比较值得关注。缺少可信结果时不使用此路线。

这些不是每篇都要套用的候选模板。两稿若只是调换同一串术语，尚未比较叙事。先用普通领域语言写清关键操作，再决定哪些专用名称必须留下。

制作“留在入口／压成支持／移到正文位置”的简短记录。比较同样事实和同等范围，不靠改变比较口径、删掉负结果或隐藏限定取胜。入口之外的独有信息必须已落到实际段落，不能只在报告里写“移至方法”。

## 摘要与引言共同承担工作

摘要先建立问题、主要变化与最有判别力的结果，再用贴近该结果的限定界定它。先区分两类信息：改变结果含义的比较口径或归因边界留在结果附近；实现归属、未胜出的替代方案与次级发现由引言、对应结果段或讨论承接。继承关系可压入机制句，但不能隐藏。若删去替代方案会使摘要错误暗示各组件都已独立贡献收益，就保留必要区分；否则不让该方案在主结果之后重新开启一条主线。不是按字数删减，而是给每条事实确定论证职责和实际落点。引言可用一个具体操作承接摘要，随后区分已有机制与本文改变，再解释验证为什么有判别力。不要让摘要、贡献段和方法首段重复同样的定义串。

方法从必要困难进入：谁可能冲突、什么成本可能抵消收益、什么边界限制表示。实验从待判断的问题进入，再给配置。负结果和失败控制仍在对应结论附近，不因追求顺畅而藏到远处。

## 用产物而非作者理由选择

先给未看编辑理由的审阅者同等范围材料，记录其复述、误读和必须回查之处，再打开全文核对。可用已有 `make_review_packet.py` 定范围导出；审阅材料不附变更理由或答案。若审阅者先读过全文，应明确记为定位复核。

候选让主贡献更易指出，却增加歧义或压没重要工作时，先修该代价。没有可辨改善则保留较好原稿；不按减字比例或模型总分选胜者。示例见[完整对照](worked-examples.md)。结构不同的[旋塞选择器示例](selector-hierarchy.md)展示在没有性能数据时，如何保留机制主线并把未评估替代方案放到对应位置。
