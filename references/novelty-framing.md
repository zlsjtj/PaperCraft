# 让主线贯穿论文入口

先按[审阅方法](reviewer-method.md)确定有证据支持的主线，再安排各处信息，避免把同一段话复制五次。

| 位置 | 读者应获得的信息 | 常见问题 |
|---|---|---|
| 标题 | 研究对象和具体机制或用途 | 未经证明的“最优”“统一”，堆满实现步骤 |
| 摘要 | 约束、实际改变、主要结果及比较口径、重要边界 | 用最好个例代替完整结果 |
| 引言 | 约束为什么重要，最近工作还缺什么，本文增加了什么能力 | 给已有技术换名，贡献只有清单没有价值 |
| 主图 | 可核对的对象关系、执行方式或状态变化 | 只画一个“优化”方框，把占用率画成性能 |
| 结论 | 证据允许作出的判断或选择，以及适用范围 | 新增未经论证的主张，重复摘要 |

机制与应用是两种切入角度，按学科选择。物理因果需要相应证据；系统论文可解释执行、正确性、资源约束及完整工作负载结果。合理解释仍可能只是待验证假设。

主线已清楚时保留标题与摘要；定位不清时，在内部比较两三个真正不同的候选，选证据充分且有实质价值的一条。局部修改不必额外设计多个标题。

每个价值判断应能找到直接做法的限制、设计变化及结果。验证工作可以因区分失败类型而重要，混合结果也可以支持有条件的选择，不需要夸大数字或拆出虚假的独立贡献。参见[完整示例](worked-examples.md)。
