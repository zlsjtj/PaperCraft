# 从诊断到真实交付

## 基线与短计划

全文修订先读完整正文与图表；局部请求只查必要上下文。留输入路径、SHA-256、机制/证据版本、目标和独立输出目录。续改必须识别上轮候选、已接受修改和仍未解决的问题。不得以旧项目待办替代当前材料检查。

建立 [贡献证据表](../templates/claim-evidence-ledger.md)，再用 [计划](../templates/revision-plan.md) 说明要解决的几个具体阅读问题，数量由材料决定。原稿报告的数字可以忠实保留，但不能标成原始数据已复核。缺失记录集中进入作者确认表，有证据的部分继续改。

## 三路处理

分别使用 [创新](novelty-framing.md)、[工作量](workload-framing.md)、[呈现](presentation-review.md)。顺序执行足够；如果宿主和当次授权允许多个 Agent，让各路返回条目或补丁，不直接覆盖同一个 Word。每条建议带原文位置、拟改文、证据 ID、范围和保留条件。

创新路确定主线和关键落点；工作量路解释实现/实验选择和漏写的完成工作；呈现路处理术语、图表、格式与阅读成本。三路不是三个必须宣称的新贡献。

重要修改须回答四项：原稿哪里不够清楚、具体改善了什么、依据来自哪里、结论仍受什么条件约束。先判断是否已有明确机制、充分技术决策和准确证据；若已有，保留而不为增加工作量再改。选择有价值的展开，不以字数、标题数或术语数作为效果指标。

## 主编辑合并

为冲突记录：候选说法、各自证据、选用版本及原因。例如静态容量可容纳更多 lane，而计时无改善时，保留容量结论及计时负结果，不能合并为“容量提升带来加速”。无依据的因果建议留在报告的后续研究，不进入已证实结论。

检查标题—摘要—引言—核心图—结论：同一机制、比较对象、证据层级和边界一致；各入口承担不同作用。审核参数选择的时间顺序，避免后见解释变成预先标定。新增分析记录输入哈希、脚本/计算、执行时间和探索性性质。

## 文件与审阅

全文默认交付黄色审阅 Word 和中文报告 Word；不要只交 Markdown 报告或改写建议。复杂 Word 用现有 documents 工作流做局部 OOXML 修改，勿抽纯文本重建整稿。简单段落可用 [可执行辅助工具](docx-helper.md)。两种路径均需 [变更映射](../templates/change-map.md) 与最终渲染。报告含 [模板](../templates/diagnostic-report.md) 的必要信息，不必机械加十个空标题。

公式相邻段、域和交叉引用按 [复杂 Word 路径](complex-word.md) 继续完成；保守 helper 的拒绝不能当作整篇任务完成。图形任务按 [交接单](../templates/figure-handoff.md) 传递对象、关系、锁定数据、图文引用和实际尺寸，返稿按 [联合核查](figure-handoff.md) 验收。

已完成的图交源文件/导出文件并写实际检查；建议图标为未绘制；保留图标为保留且检查了什么。没有原始数据的定量图不能用教学数字替代。审阅者应能从改动 ID 找到原段、改段、删除/移动目的及证据。

## 验收与停止

记录五个不同状态：自动文件检查、内容编辑检查、逐页视觉检查、作者认可、投稿/公开。不得让脚本替作者设置认可。提供真实可打开文件；明确未完成视觉检查或文献/数据复核。修订证据闭合、文件已检查、剩余问题明确时停止，不因用户期待更强结果而无限扩写。

只诊断不生成修订稿；只改一段不顺带全篇重构；实验待完成时只冻结依赖它的结果。任何新实验、公开和投稿都按另行授权执行。
