# 研究故事与主图一起选择

这是热传输演示的实际开发取舍，全部材料为DEMO，不是求解器实验或文献首创。完整材料、前稿、候选、成图和入稿见[案例](../examples/heat-story/README.md)。它说明编辑怎样作选择，不提供通用论文结构。

## 同样材料，为什么一段更容易进入

前稿摘要从固定刷新频率直接转入端点快照、面所有者、指数测试与内存，然后比较三种方法。事实较完整，但在读者还不知道快照为何重要时，已经要求他评估好几种成本。

**以结果进入的候选：**先说固定刷新更快却在四种情况下不合格，再介绍有保护的复用、内存成本及所有权。它突出采用条件，但第一次接触材料的读者尚不理解被比较的操作；方法名称代替了问题画面。

**选用的机制入口：**温度变化很小时，反复计算同一类导热系数可能浪费工作。跨组的一个面又依赖两边温度：邻组刷新时，如果覆盖了用来判断旧系数的温度快照，检查就失去了原来的参照。让系数与两个快照随同一个所有者保留，才使独立刷新有一致依据。随后问这种判断成本何时值得付。

这里没有新造贡献名称，也没有把系统收益归给一个未经消融的字段。收益是读者先理解一项必要决定，再理解对照。代价是比最短入口多保留了一个具体失败情境；它有解释职责，不能为了少字删掉。

实际英文入口用普通领域语言交代关系：

> Reusing them can save work, but independently refreshed cell groups must judge each stored conductance against the temperatures that produced it. We keep both endpoint snapshots with the face coefficient's owner, so a neighbor's refresh cannot change that reference state.

机制边界接在相关判断旁：局部系数变化界不保证全局温度准确；结果同时比较误差和总时间，不能只报减少了多少系数计算。固定刷新在慢变化场景已经足够，是研究选择的一部分，而不是应当删去的反例。

## 工作量为什么不再像清单

“存快照、检查阈值、处理失败”只说明做过什么。完整段落先展示跨组刷新如何破坏参考状态，再解释快照归属为何必要。另一段说明减小步长可以修复过大的扩散行和，却不能修复同一旧温度引起的指数溢出，因此需要区分重试和退出。两项工作分别保护一致判断与有效提交，不拆成两项额外创新。

结果也分别承担职责：便宜的固定计划检验是否需要自适应；快速变化和小网格检验判断开销是否收回；容差扫描检验局部界是否足以决定最终精度。Discussion 把这些观察连成采用条件，不再顺序复述全部字段。没有性能轨迹的演示继续保留这一限制。

## 图文怎样分工

正文先让读者理解跨组面为什么依赖两个时间快照。主图负责显出同一个系数及其两端参照，在邻组刷新时什么改变、什么保留。确定性的索引所有权、完整推导和失败出口留在正文；它们不需要同时成为图的主视觉。必要标签与示例条件由图注承接，不能让图注否定画面。

主图方案应以完整图片比较，不凭“状态对比”“更多空间感”等词选胜者。图2的二维结果编码保留总时间、误差和负结果；整套图无需采用同一种布局。最终把选中的图、摘要、图注及结果放在同一篇论文里，核对读者先形成的认识与实际证据一致。

这个已知案例适合开发和复现。维护者在反馈后修好它，不是未见材料上的首次成功；迁移能力必须另用原始材料而非给定主旨检验。局部造型练习不能代替这一检验。
