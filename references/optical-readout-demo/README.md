# 从组件清单改成机制解释

本例是独立上下文中的原创教学试用，不是真实研究结果。先读 [输入](input.md)，再看 [两个实际改写候选](comparison.md)。执行者只收到任务书、候选技能和运行时路径，没有收到 SegQ 的段落或构图答案。

原段列出了组件、减法、除法和四次检查，却没有让读者知道为什么需要参考通道。选用稿从 T1 混合了哪些因素进入，解释公共快门的位置和两态读数，再把“先检查分母”连到无效状态。四个构造案例保留具体覆盖范围，没有升级成仪器性能。

从证据进入的另一稿也实际写出，但对不了解 R/T 的读者先报 q 与无效结果，会推迟动机。选用稿更长，这是让之前隐藏的因果关系显式化的篇幅代价；末尾限制仍较密，不能把这个选择称作全局最优。

这次试用证明候选方法在另一类材料中能产生具体的解释差异。它不是人类理解率测试，也没有做旧、新技能的随机因果比较。图形及可搬移的重建脚本见 FigureCraft 的 examples/optical-readout；本技能独立安装不需要该示例的绘图运行时。
