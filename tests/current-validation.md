# 2.19.0：全文编辑路径与新材料试用

基线为 2.18.0，提交 `2dceecf2c824661767d7f8a0dbe842e78e51bd1f`，开始时仓库干净，安装副本与基线一致。版本号标识本次指令、参考和示例变化，不代表已经证明写作质量普遍提升。Word 编辑器、保护脚本及原有测试接口未改。

## 复盘后改了什么

前轮确有文字改善，也存在两个断点：已有操作示例和专项参考未稳定进入实际读取；不少关键改进是在父任务或外部评审指出后才完成，不能都算作技能自主首轮表现。源记录能够确认漏读和事后修复；“指导分散导致漏读”仍是原因假设。

入口收拢到 `reviewer-method.md`，连读既有完整示例后实际成稿。`result-pair-example.md` 改成贯穿题目、摘要、方法、退出路径和结果的完整取舍案例；保留抽象改写损失具体含义的反例。简化 `revision-workflow.md`、论证记录和默认提示。另修正依赖说明：复杂段落的普通文字片段有受控接续路径，不再笼统称为只支持简单段落。

初次新材料对照后，只再改一项行为：原始记录完整保留，不等于把每个附件字段和轨迹时刻都补进正文。是否新增一段由它回答的实际问题决定，不删不利证据或必要条件。随后冻结行为文件，再换材料生成；未根据第二次评语继续调整指令或正文。

## 实际生成与得失

两份材料均由另一上下文构造，明确标为虚构演示，没有真实程序性能、物理实验或文献新颖性。生成者得到原稿、实现说明、结果表和来源条件，没有得到评审清单、预写贡献或布局答案。生成与审阅使用独立上下文、继承相同模型设置；无严格 token 配额、固定随机种子或真人参与。每次保留完整首稿及一次自主复读稿。格式转换器由各条件共用，不改正文措辞，其修复不计作技能优势。

| 材料与条件 | 实际结果 | 不能据此声称什么 |
|---|---|---|
| 后台准入控制：普通提示、旧版、开发候选 A | 数字与边界均正确。旧版的因果链较连贯，普通提示的职责和统计口径较稳；A 的比较导航较强，但生命周期段密集，结果标题未完整涵盖其内容。匿名审阅没有选出全面胜者。 | A 不是最终冻结版；这一材料后来用于修改指导，不能继续称为独立留出验证。 |
| 热输运系数复用：旧版与最终候选 B | 两稿总体相当。B 更直接解释跨组快照为何须对应同一次系数刷新，首页误差口径更自足，主表少一列重复条件而较易扫描。旧版更突出完整成本判断，接受路径与容差章节导航更明确。 | 没有证明 B 稳定胜过旧版或普通提示；第二份没有普通提示组，未做重复采样，也未在真实未编辑长稿上再验证。 |

两次评审均先看匿名、打乱身份的同范围前部并封存，再看全文、材料与实际页面。第二份逐字段恢复表题公共常量，核对两表 18+6 条记录、六条公式及所有失败分支；没有发现数值或主张扩大。结果属于模型辅助阅读，不是审稿人认可。

仍有实际阅读负担：两版都比原开发稿长，最终候选仍有长表注、宽表和部分密集段落；线性公式未排成规范下标与分式，最后一页空间利用不佳。原稿到成稿的改善不能全部算作新版胜过旧版。没有把字数、页数或完整度作为胜出依据。

## 技术、文件与发布范围

统一入口运行 11 组套件，包含 Python 语法、原有回归、单元、复杂 Word 和 README 源码生成/build/verify，均通过。官方技能校验、实际依赖及本地链接检查另行执行。它们验证工具路径，不评价论文说服力；此前验收记录保存在 [2.18](validation-2.18.md)。

两份材料的清稿均实际生成 DOCX/PDF；最终候选附黄色稿。第二份清稿与黄稿各六页，逐页查看，逐段、逐单元格、逐公式比对源稿，并核对清黄两稿去除新高亮后的 XML 内容相等。黄色是相对输入原稿的段落级改写标记，不是原生修订或逐字红线。

共同转换器先暴露宽表数字折行及 `abs(...)` 被转换为不完整竖线的问题，保留初次记录后修复并重渲染。PDF 逐词检查仍对折行的案例名或列头发出告警，记录为需要页面复核，不伪改为自动全通过；实际页面确认字符存在，阅读代价仍保留。没有运行原生 Microsoft Word、真实打印或真人读者测试。

仓库含技能所需参考、模板、工具与开发示例；新材料、全部首稿、匿名记录、共同排版器、输出及哈希留在本地交付。两阶段行为冻结与最终安装分别有内容标识，不能只凭相同版本号把 A 的产物当作 B 的验证。没有改动 FigureCraft、SegQ 或上传未公开论文。

本轮结论是：执行路径和部分自主解释有改善，但未证明全文包装的稳定优势，面子工程仍未充分完成。保持这一边界，不把一次模型偏好写成升级成功率或期刊接收保证。
